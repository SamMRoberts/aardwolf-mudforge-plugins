# Repository Agent Instructions

## Scope and approach

These instructions apply throughout this repository unless a nested `AGENTS.md`
provides more specific guidance. Follow explicit user instructions first.

- Inspect the relevant source, tests and documentation before changing behavior.
- Prefer the smallest coherent change that preserves existing public contracts,
  installed plugin identities, saved data and user layout.
- Keep unrelated refactors, dependency updates and generated churn out of the diff.
- Never infer current behavior or verification results from an older branch or
  another worktree.

## Repository map

This project distributes Lua plugins and a shared library for MudForge, plus
standalone terrain packs. Node.js tooling builds the installable artifacts;
Python supports acceptance fixtures and the one-time legacy Spells migration.

| Path | Responsibility |
| --- | --- |
| `src/libs/aardwolf-api.lua` | Injected consumer API, protocol validation, native storage and UI helpers |
| `src/plugins/` | API Core, Vitals, Spells, Room Details and the Atlas Lua adapter/template |
| `src/atlas/` | Atlas HTML/CSS/JavaScript renderer, settings, details, fixtures and embedded artwork |
| `src/map-packs/` | Pinned terrain registries, source artwork, variants and pack metadata |
| `tools/` | Deterministic build, Lua compatibility checks, migration and disposable acceptance tools |
| `tests/` | Node test-runner suites, Fengari host fixtures and Python unit tests |
| `dist/`, `plugins.json` | Generated install files, previews and repository catalog |
| `docs/` | API contracts, component guides, migration instructions and native acceptance evidence |

Read [README.md](README.md) for setup and behavior,
[docs/API.md](docs/API.md) for shared contracts and
[docs/NATIVE-ACCEPTANCE.md](docs/NATIVE-ACCEPTANCE.md) for native validation.
Consult the Atlas and terrain-pack guides when changing those components.

## Source and generated artifacts

- Edit source under `src/` and build logic under `tools/`; regenerate `dist/` and
  `plugins.json` with `npm run build`. Do not patch generated files by hand.
- Most Lua artifacts are copied byte-for-byte. Atlas is assembled from its Lua
  template, local web documents, pinned Three.js bundle and embedded assets.
- Keep builds deterministic and independent of runtime downloads. Preserve the
  checked-in source artwork and pinned terrain IDs/names; do not silently remap
  terrain identities or merge directional/numbered variants.
- When adding a plugin or library, update the entries in
  `tools/build-repository.mjs`. Preserve required Lua metadata and semver;
  regenerate catalog hashes and sizes instead of editing them manually.
- Include affected generated artifacts with source changes. Update component
  versions and documentation when releasing changed behavior; a documentation-only
  change does not require a plugin version bump or rebuild.

## Development commands

Run from the repository root. Use the lockfile with `npm ci` when dependencies
need installing. Python 3 is required for the full test suite and converter,
but the installed plugins have no Python dependency.

```sh
npm ci
npm run build
npm test
npm run build:check
git diff --check
```

- `npm test` runs `node --test tests/*.test.mjs`, followed by Python unittest
  discovery for `tests/*_test.py`.
- Start with the affected suite, for example
  `node --test tests/api.test.mjs` or
  `python3 -m unittest discover -s tests -p 'spells_migration_test.py'`.
- After runtime or build changes, run the full suite and `npm run build:check`.
  The latter compares generated bytes without rewriting them.
- There are no separate lint or type-check scripts in `package.json`.
  For documentation-only edits, check links/paths and whitespace; runtime tests
  are unnecessary unless the edit changes executable examples or contracts.

## MudForge runtime contracts

- Lua must parse as Lua 5.1 and remain compatible with MudForge's JavaScript
  transpiler. JavaScript reserved words cannot be Lua bindings: use
  `packageName`, for example, while retaining protocol fields like `data.package`.
  Use the existing compatibility validator rather than bypassing it.
- Host table behavior can differ from a native Lua VM: numeric keys from
  `pairs()` may be strings, and optional nil-valued entries may be retained.
  Normalize at host boundaries using established helpers and add focused
  regressions for compatibility fixes.
- API Core is the single GMCP negotiation owner per session. Consumers use one
  injected `aardwolf-api` instance per plugin; subscribe before `start()` and
  stop/unsubscribe during cleanup. Keep library loading and construction free
  of host side effects.
- Preserve world/session isolation and use the actual installed plugin ID for
  targeted messages. Fence delayed callbacks against unload, identity changes
  and obsolete requests; release owned timers, subscriptions and widgets.
- Preserve partial character updates: omitted fields retain prior values,
  explicitly invalid known fields become unknown. Room/Group snapshots replace
  their previous values. Missing numbers must not become zero; Comm events
  remain transient, without replay or persistence.
- Use native plugin/world storage. Preserve schema validation, defensive copies,
  failure feedback and save/read-back checks where used. Do not reintroduce the
  removed SQLite bridge or a helper process into normal plugin operation.
  Follow [docs/SQLITE.md](docs/SQLITE.md) for legacy migration.
- Treat server text, widget messages and imported records as untrusted. Keep
  existing size/depth bounds, role/version handshakes and validation. Render
  external text as text nodes or escaped text, never raw HTML.
- Preserve scroll, focus, unfinished forms, placement and visibility during
  ordinary updates. Destroy only widgets owned by the current plugin instance.
- Atlas remains standalone and read-only: it previews routes but never walks,
  edits native map data or persists a duplicate map. Keep its assets bundled.
  Do not introduce automatic gameplay commands or refresh loops outside the
  affected plugin's documented behavior.

## Verification and native data safety

- Add meaningful behavioral regressions for changed logic. Node tests execute
  Lua in Fengari's Lua 5.3 VM with host fixtures; these do not execute MudForge's
  transpiler, native widgets, persistence engine or GMCP transport.
- Distinguish offline tests, browser rendering, native disposable-world checks
  and live Aardwolf acceptance. Report only what was actually observed for the
  tested version and environment; retain documented limitations.
- Follow the component acceptance guide for native checks. Use an explicitly
  authorized disposable world, preserve the original selection and back up
  before writes. Existing-world migrations and live connections need their own
  authorization. Terrain-pack import replaces the terrain-style list, so export
  the existing pack before importing.
- Keep credentials, world exports, private gameplay logs, database backups and
  migration output outside the repository. Migration must preserve the legacy
  source and refuse unsafe replacement of saved data.

## Git and completion

- Inspect branch, upstream, worktrees and staged/unstaged/untracked changes before
  modifying Git state. Preserve existing work and never modify a branch checked
  out in another worktree. Inspect ignored files for collisions before switching
  branches or integrating changes.
- Fetch before substantial development and synchronize against the remote primary
  branch when needed. Do not automatically stash, rebase, force-reset or discard
  work. Follow the user's Git preservation and synchronization instructions.
- Commits, pushes, merges of PRs, branch deletion and publication require explicit
  authorization; safe synchronization merges follow the user's stated policy.
- Review the final diff for unintended source/generated changes. Report the
  outcome, checks actually run and any remaining native or live validation gaps.
