# Repository CI

[Repository verification](../.github/workflows/verify.yml) runs on every pull
request, including documentation changes. The supported CI combination is
**Node.js 24.x, its bundled npm, and CPython 3.14.x on Ubuntu 24.04**. The job
prints the resolved patch versions. Python tests use the standard library;
JavaScript dependencies are installed from `package-lock.json` with `npm ci`.

The workflow tests GitHub's pull request merge result. Checkout fetches history
so `git diff --check "$PR_BASE_SHA" HEAD` can inspect the complete difference
between the event's base commit and that merge result. A plain `git diff --check`
would inspect only unstaged edits and miss whitespace already committed in a PR.

The checks run in this order:

1. Validate whitespace in the PR diff.
2. Install locked dependencies with `npm ci`.
3. Compare committed generated bytes with `npm run build:check`.
4. Run `npm test` (Node tests, then Python unittest discovery).

CI never runs `npm run build` or writes generated outputs before comparison.
`build:check` computes expected bytes in memory and fails for missing or stale
files. To fix stale outputs, run `npm run build` locally, review the changes and
include the affected generated files with the source changes.

The workflow has only `contents: read` permission, does not persist checkout
credentials, pins actions to commit SHAs and has a 15-minute timeout. It uses the
`pull_request` event so fork code does not execute in a privileged target event.
It has no publication, deployment, native MudForge or live Aardwolf steps.
Offline fixture results retain the limits described in
[native acceptance](NATIVE-ACCEPTANCE.md).

The optional [browser smoke command](BROWSER-SMOKE.md) runs separately from this
workflow and `npm test`. It requires the pinned Playwright Chromium installation
and produces synthetic-browser evidence; this offline job does not establish a
browser pass.

## Local verification and failure probes

With the supported runtimes selected, verify a clean checkout without rebuilding:

```sh
npm ci
npm run build:check
npm test
git diff --check origin/main...HEAD
```

Run the following probes from a clean, committed checkout of the revision being
evaluated. `git archive HEAD` copies committed files only, so it does not test
uncommitted edits. All deliberate corruption happens in a new temporary
directory outside the checkout; no world data or installed plugins are used.

```sh
CI_PROBE_DIR=$(mktemp -d)
git archive HEAD | tar -x -C "$CI_PROBE_DIR"
(
  set -eu
  cd "$CI_PROBE_DIR"
  npm ci
  npm run build:check
  npm test

  # Stale generated bytes must fail comparison and remain unchanged by the check.
  cp dist/libs/aardwolf-api.lua original-api.lua
  printf '\n-- intentional stale CI probe\n' >> dist/libs/aardwolf-api.lua
  cp dist/libs/aardwolf-api.lua stale-api.lua
  if npm run build:check; then
    echo 'ERROR: stale artifact passed comparison' >&2
    exit 1
  fi
  cmp stale-api.lua dist/libs/aardwolf-api.lua
  mv original-api.lua dist/libs/aardwolf-api.lua
  rm stale-api.lua
  npm run build:check

  # A test failure must propagate through the same npm test command used by CI.
  cat > tests/ci-failure-probe.test.mjs <<'JS'
import test from 'node:test';
import assert from 'node:assert/strict';
test('intentional CI failure probe', () => assert.fail('intentional CI probe'));
JS
  if npm test; then
    echo 'ERROR: failing test passed npm test' >&2
    exit 1
  fi
  rm tests/ci-failure-probe.test.mjs
  npm test
)
```

Confirm the failing commands report the stale `dist/libs/aardwolf-api.lua` and
the named intentional test respectively; an unrelated setup failure does not
establish failure detection. Retain logs with the tested revision, OS and exact
runtime versions. These local probes establish command behavior; only a hosted
pull request run establishes GitHub event handling, runner setup and job status.
